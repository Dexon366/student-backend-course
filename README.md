## 🔄 Лабораторная работа №2 — CRUD API

📂 [`lab2-crud`](./lab2-crud/)

Во второй лабораторной работе рассматривается создание серверного API с реализацией основных CRUD-операций.

### CRUD

**CRUD** — это четыре базовые операции работы с данными:

| Операция   | Назначение       | HTTP-метод      |
| ---------- | ---------------- | --------------- |
| **Create** | Создание данных  | `POST`          |
| **Read**   | Получение данных | `GET`           |
| **Update** | Изменение данных | `PUT` / `PATCH` |
| **Delete** | Удаление данных  | `DELETE`        |

### В рамках работы рассматриваются

* создание REST API;
* HTTP-методы;
* маршрутизация;
* endpoints;
* обработка запросов;
* обработка JSON;
* CRUD-операции;
* HTTP-коды состояния;
* тестирование API;
* работа с **Postman**.

Для проверки API также используется коллекция запросов:

## 🔀 Лабораторная работа №3 — Маршрутизация и параметры запросов

📂 [`lab3-routing-params`](https://github.com/Dexon366/student-backend-course/tree/main/lab3-routing-params)

В третьей лабораторной работе рассматривается создание REST API на **Express.js** с использованием параметров маршрутов, query-параметров и вложенных маршрутов.

В рамках работы реализован API для работы с двумя связанными сущностями — **заказами и клиентами**.

**Вариант:** 6
**Уровень:** Продвинутый

### Маршрутизация

**Маршрутизация** — это механизм сопоставления HTTP-запросов с определёнными обработчиками приложения.

В лабораторной работе используются параметры маршрутов:

```text
/orders/:id
/clients/:clientId/orders
/clients/:clientId/orders/:orderId
/statuses/:status/orders
```

а также query-параметры:

```text
/orders?search=...
/orders?sort=...&order=...
/orders?page=...&limit=...
/orders?status=...
```

### В рамках работы рассматриваются

* создание REST API на Express.js;
* маршрутизация;
* параметры пути `req.params`;
* query-параметры `req.query`;
* вложенные маршруты;
* несколько параметров маршрута;
* поиск;
* сортировка;
* пагинация;
* фильтрация;
* связь заказов по статусу;
* статистика;
* валидация параметров;
* обработка HTTP-кодов `400`, `404` и `500`;
* wildcard-маршруты;
* логирование запросов;
* автоматический перезапуск сервера с помощью **Nodemon**;
* тестирование API в **Postman**.

Для проверки API также используется коллекция запросов:

📄 [`Lab3_Orders.postman_collection.json`](https://github.com/Dexon366/student-backend-course/blob/main/lab3-routing-params/Lab3_Orders.postman_collection.json)

## ▶️ Как запустить проекты

Общий принцип запуска зависит от конкретной лабораторной работы.

Для Node.js-проектов:

```bash
npm install
npm start
```

После запуска сервер обычно становится доступен по локальному адресу, указанному в README соответствующей лабораторной работы.

Для Python-проектов используется виртуальное окружение и установка необходимых зависимостей:

```bash
python -m venv venv
```

После активации виртуального окружения устанавливаются зависимости из `requirements.txt`.

> ℹ️ Точные команды запуска и проверки указаны в README каждой лабораторной работы, поскольку они могут отличаться.
