```bash
cd lab1-first-http-server
```

```bash
npm install
```

## Логирование запросов

Для регистрации входящих HTTP-запросов используется middleware.

В терминале отображаются:

* дата и время запроса;
* HTTP-метод;
* адрес маршрута.

Пример:

```text
[2026-09-13 09:20:01] GET /
[2026-09-13 09:20:05] GET /api/orders
[2026-09-13 09:20:10] GET /api/clients
[2026-09-13 09:20:15] GET /api/orders/5
[2026-09-13 09:20:20] GET /abc
```

Проверка выполнена изменением текста, возвращаемого главной страницей.

# ⚖️ Сравнение реализаций

Оба сервера реализуют одинаковую функциональность, однако используют разные технологии и подходы.

| Характеристика    | Node.js + Express | Python + Flask           |
| ----------------- | ----------------- | ------------------------ |
| Язык              | JavaScript        | Python                   |
| Фреймворк         | Express           | Flask                    |
| Основной файл     | `app.js`          | `app.py`                 |
| Формирование JSON | Express           | `jsonify()`              |
| Маршрутизация     | `app.get()`       | `@app.route()`           |
| Параметр маршрута | `:id`             | `<int:order_id>`         |
| 404               | Middleware        | `@app.errorhandler(404)` |
| Автоперезапуск    | Nodemon           | Flask Debug Mode         |
| Порт              | `3000`            | `3000`                   |

Таким образом, одна и та же задача может быть реализована как с использованием JavaScript и Node.js, так и с использованием Python и Flask.

# Контрольные вопросы

## 1. Что такое клиент-серверная архитектура?

**Клиент-серверная архитектура** — это модель взаимодействия, при которой клиент отправляет запросы серверу, а сервер обрабатывает их и возвращает ответ.

Например, браузер является клиентом: он отправляет запрос на сервер сайта, а сервер возвращает HTML-страницу, данные или другую информацию.

Основные элементы:

* **Клиент** — отправляет запросы и получает ответы.
* **Сервер** — принимает запросы, обрабатывает их и возвращает результат.

---

## 2. Какой протокол используется для общения клиента и сервера в вебе?

В веб-разработке для общения клиента и сервера используется протокол **HTTP (HyperText Transfer Protocol)**.

Также существует защищённая версия протокола — **HTTPS**, которая использует шифрование для защиты передаваемых данных.

HTTP используется для таких операций, как получение данных, отправка данных, создание и удаление ресурсов.

---

## 3. Что такое эндпоинт (endpoint)?

**Endpoint (эндпоинт)** — это конкретный адрес на сервере, по которому клиент может обратиться для выполнения определённого действия или получения данных.

Например:

```text
GET /users
GET /users/5
POST /users
```

Здесь `/users` и `/users/5` являются эндпоинтами API.

Эндпоинт обычно определяется комбинацией **HTTP-метода и URL-пути**.

---

## 4. Какую структуру имеет HTTP-запрос и HTTP-ответ? Что такое код состояния (status code)?

### HTTP-запрос

HTTP-запрос обычно состоит из:

1. **Стартовой строки** — HTTP-метод, путь и версия протокола.
2. **Заголовков (headers)** — дополнительная информация о запросе.
3. **Тела (body)** — данные, которые клиент отправляет серверу. Тело присутствует не во всех запросах.

Пример:

```http
POST /users HTTP/1.1
Content-Type: application/json

{
  "name": "Ivan"
}
```

### HTTP-ответ

HTTP-ответ состоит из:

1. **Стартовой строки** — версия HTTP и код состояния.
2. **Заголовков**.
3. **Тела ответа** — данные, которые сервер возвращает клиенту.

Пример:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "name": "Ivan"
}
```

**Status code (код состояния)** показывает результат обработки запроса сервером.

Основные группы кодов:

* `1xx` — информационные;
* `2xx` — успешное выполнение;
* `3xx` — перенаправление;
* `4xx` — ошибка со стороны клиента;
* `5xx` — ошибка сервера.

---

## 5. Что такое JSON? Почему он популярен в веб-разработке?

**JSON (JavaScript Object Notation)** — это текстовый формат для хранения и передачи структурированных данных.

Пример JSON:

```json
{
  "name": "Ivan",
  "age": 18,
  "student": true
}
```

JSON популярен в веб-разработке, потому что он:

* имеет простой и понятный синтаксис;
* легко читается человеком;
* легко обрабатывается программами;
* поддерживается практически всеми современными языками программирования;
* часто используется для обмена данными между клиентом и сервером через API.

## 7. Что такое автоматический перезапуск сервера и зачем он нужен? Какой пакет используется для Node.js?

**Автоматический перезапуск сервера** — это возможность автоматически перезапускать сервер после изменения файлов проекта.

Это удобно во время разработки, потому что после каждого изменения кода не нужно вручную останавливать и снова запускать сервер.

Для Node.js часто используется пакет **nodemon**.

Установка:

```bash
npm install --save-dev nodemon
```

Запуск:

```bash
npx nodemon app.js
```

После изменения исходного кода `nodemon` автоматически перезапустит сервер.

## 8. Какие коды состояния HTTP вы знаете? За что отвечает код 404?

Примеры HTTP-кодов:

* `200 OK` — запрос успешно выполнен;
* `201 Created` — ресурс успешно создан;
* `400 Bad Request` — некорректный запрос;
* `401 Unauthorized` — требуется аутентификация;
* `403 Forbidden` — доступ запрещён;
* `404 Not Found` — запрашиваемый ресурс не найден;
* `500 Internal Server Error` — внутренняя ошибка сервера.

Код **404 Not Found** означает, что сервер не смог найти ресурс по указанному адресу.

Например, если клиент отправит запрос:

```text
GET /users/999
```

а пользователя с таким ID не существует, сервер может вернуть:

```http
404 Not Found
```

## 9. Что такое middleware в Express / декораторы запросов во Flask?

**Middleware** в Express — это функция, которая выполняется между получением HTTP-запроса и отправкой ответа клиенту.

Middleware может:

* проверять данные пользователя;
* записывать информацию о запросах в лог;
* изменять объект запроса или ответа;
* проверять авторизацию;
* передавать управление следующему обработчику.

Пример middleware в Express:

```javascript
app.use((req, res, next) => {
  console.log(req.method, req.url);
  next();
});
```

`next()` передаёт выполнение следующему middleware или обработчику маршрута.

Во Flask похожая логика может реализовываться с помощью обработчиков и декораторов, например:

```python
@app.before_request
def before_request():
    print("Получен запрос")
```

Декоратор `@app.before_request` позволяет выполнить функцию перед обработкой каждого запроса.

## 10. Как получить параметр из URL-пути (например, ID пользователя) в вашем фреймворке?

В Express параметр можно указать непосредственно в маршруте с помощью двоеточия:

```javascript
app.get('/users/:id', (req, res) => {
  const id = req.params.id;
  res.send(`User ID: ${id}`);
});
```

Если клиент отправит запрос:

```text
GET /users/15
```

то значение:

```javascript
req.params.id
```

будет равно:

```text
15
```

Во Flask параметр указывается непосредственно в URL:

```python
@app.route('/users/<int:id>')
def get_user(id):
    return f"User ID: {id}"
```

При запросе:

```text
GET /users/15
```

переменная `id` будет содержать значение `15`.

В ходе лабораторной работы был создан простой HTTP-сервер и изучены основные принципы обработки HTTP-запросов.

Были реализованы основные GET-маршруты, возвращающие текстовые и JSON-ответы, параметризированный маршрут для получения данных по идентификатору, обработка ошибки `404`, логирование запросов и автоматический перезапуск приложения при изменении исходного кода.

Практическая часть была выполнена двумя способами: с использованием **Node.js + Express** и **Python + Flask**. Сравнение реализаций показало, что оба подхода позволяют достаточно просто создавать HTTP-серверы и организовывать маршрутизацию, при этом отличаются синтаксисом и используемыми инструментами.

---

## 🚀 Быстрый запуск

### Node.js + Express

```bash
npm install
npm run dev
```

### Python + Flask

```bash
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python app.py
```

После запуска любого из серверов открыть:

```text
http://localhost:3000
```
